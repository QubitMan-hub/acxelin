Post-quantum TLS in front of services that cannot change.

Acxelin TLS is an edge proxy with its own certificate authority. A client that cannot do post-quantum key exchange is refused; the service behind the edge keeps running exactly as it is.

Where the edge sits

Traffic recorded today can be decrypted once a quantum computer exists. The edge protects the part of the path that crosses the network, and neither end has to change.

The service can be anything that listens on a port: a web application, PostgreSQL, pgvector, MQTT. acxelin-tls bundle nginx --host web.example.com writes the certificates, the edge configuration and a compose file. For mutual TLS, the edge also requires a client certificate from your own authority, and refuses a revoked client as soon as it has the new revocation list.

Three policies

What each one lets a connection negotiate, read from the product's own policy table when this page was built. A hatched key marks a classical, quantum-exposed group.

Nothing falls back silently. A connection that cannot meet the policy ends, and the edge's log says which side lacked what.

Your own certificate authority

Certificates are ML-DSA, the post-quantum signature standardised in FIPS 204. You run the authority that issues them.

Issue, renew and revoke from the console in Fig. 3 or the command line; a daily ca maintain renews what expires soon and re-signs the revocation list.

Machines enrol with a one-time token over EST (RFC 7030), and standard ACME clients such as certbot obtain ML-DSA certificates over ACME (RFC 8555). Keep the root offline and issue from an intermediate authority; its key can live in AWS KMS or behind your own signing command.

Where it runs

Docker

One image with OpenSSL 3.5 included, published to GHCR with each release. With no arguments it runs the tour in Fig. 1.

docker run --rm ghcr.io/acxelinquantum/acxelin-tls:{{VERSION}}

systemd

A unit for the edge, and a timer that runs authority maintenance daily. Both ship in the release folder.

systemctl enable --now acxelin-tls-edge

What it does not claim

  • Browsers trust only public certificate authorities, and those do not issue ML-DSA certificates yet. For browsers, the transition policy serves a classical fallback certificate, so a visitor's identity check is only as strong as classical TLS; the key exchange is post-quantum either way.
  • A revoked certificate works until the edge next fetches the revocation list: every 60 seconds by default for an edge that follows one.
  • The service behind the edge sees plain traffic. Keep it on loopback or a private network.
  • Signing through AWS KMS or your own command has not yet been run against real HSM hardware.
