Set up Acxelin TLS

It needs Python 3.11 to 3.14 and OpenSSL 3.5 or newer. You do not need another Acxelin product, and nothing contacts Acxelin Quantum.

  1. Download

    From the release page, save two files in the same folder:

    • acxelin-tls-{{VERSION}}-wheelhouse.tar.gz: the program
    • SHA256SUMS: a fingerprint of every file in the release

    Then open a terminal in that folder. On Windows, use PowerShell.

  2. Check the download

    This confirms the file is exactly the one we published, not damaged or changed on the way. It only reads the file.

    Linux

    sha256sum -c SHA256SUMS --ignore-missing

    You should see the file's name followed by OK.

    macOS

    shasum -a 256 acxelin-tls-{{VERSION}}-wheelhouse.tar.gz

    Windows

    Get-FileHash .\acxelin-tls-{{VERSION}}-wheelhouse.tar.gz

    On macOS and Windows this prints the file's fingerprint, a long string of letters and numbers. It should match the one next to the file's name in SHA256SUMS (capital or small letters do not matter).

    If the check fails, delete the file and download it again. Do not install it.

    Optional: confirm who built it

    If you use the GitHub command line, this shows that our release workflow built the file from this repository:

    gh attestation verify acxelin-tls-{{VERSION}}-wheelhouse.tar.gz --owner AcxelinQuantum

    You should see Verification succeeded.

  3. Unpack it

    tar xzf acxelin-tls-{{VERSION}}-wheelhouse.tar.gz
cd acxelin-tls-{{VERSION}}-wheelhouse

    This creates the folder acxelin-tls-{{VERSION}}-wheelhouse and moves into it. The same two lines work in PowerShell.

  4. Install

    Still in that folder:

    sh install.sh

    On Windows, the first line tells Windows you trust this downloaded script, and the second runs it:

    Unblock-File .\install.ps1
powershell -ExecutionPolicy RemoteSigned -File .\install.ps1

    It installs from the wheels in the folder, offline, then runs acxelin-tls doctor. You should see each check and Start here with the next commands.

    What it changes
    A private Python environment in ~/.acxelin/tls and the command ~/.local/bin/acxelin-tls. On Windows, %LOCALAPPDATA%\Acxelin\tls and %LOCALAPPDATA%\Acxelin\bin, which it adds to your user PATH. No administrator rights, nothing system-wide.
    OpenSSL 3.5
    It uses the system's when it is new enough, otherwise Homebrew's, or the folder in ACXELIN_OPENSSL. On Windows: choco install openssl, then run the installer again.
    Remove it
    sh install.sh --uninstall, or install.ps1 -Uninstall. Your authorities, certificates and settings stay where you put them.

  5. See it work

    A one-minute tour that needs nothing set up. In a temporary folder it creates an authority, puts the edge in front of a small web server, and shows a post-quantum client getting in and a classical one being turned away. It deletes everything when it ends.

    acxelin-tls try

    Five numbered steps, each saying what happened. The demo shows the same output, frame by frame.

  6. Create your certificate authority

    The authority signs every certificate your edges and clients use. You can also do this step and the next in the console (step 9).

    acxelin-tls ca init --name "Example Root CA" --dir pki

    It asks you to choose a passphrase, which protects the authority's key. Keep it somewhere safe: you need it to issue or revoke certificates. The folder pki now holds the authority; only you should be able to read it.

  7. Issue the edge's certificate

    The edge shows this certificate to clients, so name it after the address clients connect to.

    acxelin-tls ca issue server web.example.com --dir pki --out web

    The folder web now holds the certificate (chain.pem) and its key (key.pem).

  8. Put the edge in front of your service

    Here the service listens on port 8080 of this machine, and clients reach it through the edge on port 8443:

    acxelin-tls edge --listen 0.0.0.0:8443 --target 127.0.0.1:8080 --cert web/chain.pem --key web/key.pem

    The edge says it is listening and keeps running until you stop it. Clients now connect to port 8443 with post-quantum TLS 1.3, and the service itself does not change.

    0.0.0.0 means every network interface. Open port 8443 in your firewall only to the clients that need it, and keep the service on 127.0.0.1 or a private network.

    Optional: only let in clients with a certificate (mutual TLS)

    Add these to the edge command, and issue each client a certificate with acxelin-tls ca issue client NAME --dir pki --out NAME:

    --require-client-cert --ca pki/ca.crt --crl pki/crl.pem
    Optional: several services in one edge

    Write the routes in an edge.toml, starting from config/example.toml in the release folder. Check it, then start the edge from it:

    acxelin-tls doctor --config edge.toml
    acxelin-tls edge --config edge.toml

  9. Open the console

    The console does the same work in your browser: create the authority, issue and revoke certificates, see each running edge and its policy, test a connection, and read the health checks.

    acxelin-tls console

    Your browser opens, already signed in. The console holds the authority's passphrase in memory only, so it asks again after a restart.

    On a remote server

    The console listens only on the machine it runs on. Forward a port, then ask the running console for a fresh link:

    ssh -L 8900:127.0.0.1:8900 server
acxelin-tls console link --port 8900

    Run the second command in that SSH session and open the address it prints on your laptop.

    In Docker

    docker run -v acxelin-tls:/data -p 127.0.0.1:8900:8900 ghcr.io/acxelinquantum/acxelin-tls:{{VERSION}} console --container
docker exec -it NAME acxelin-tls console link

  10. Keep it running

    Once a day, the authority must renew certificates that are close to expiring and publish a fresh revocation list:

    acxelin-tls ca maintain --dir pki

    The release folder has systemd units and a daily timer that run it for you. Before you go to production, read what Acxelin TLS defends against and the manual.
