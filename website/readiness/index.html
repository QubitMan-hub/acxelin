Why RSA ranks high today

Traffic and backups recorded now can be decrypted once a quantum computer exists. An asset is urgent when the years its data must stay secret, plus the years your migration takes, run past the year that computer is assumed to arrive.

You set all three numbers, and a CMDB export can set the first one per system: chat kept for a year ranks lower than health records kept for twenty-five. The sample used the defaults.

What one scan reads, and what it writes

Cryptography hides in more places than code. One scan covers them, and every scan writes the same files to readiness-out/.

Where it runs

In every pull request

Fail the build only on cryptography a change introduces, by comparing with the CBOM from the main branch.

acxelin-readiness scan . --baseline cbom.json --fail-on high

For an audit

Check against NIST IR 8547, the NSA's CNSA 2.0 suite and India's DST roadmap (2029), and fail when a rule is already broken.

acxelin-readiness scan . \
  --policy nist-ir-8547 --policy india-dst \
  --fail-on-policy

On a schedule

Scan again every day and hear only when something appeared or disappeared since the last scan.

acxelin-readiness watch . --every 24 \
  --on-change "notify-team"

By business service

Name each path's owner, service, how long its data must stay secret and how important it is, and the ranking follows.

acxelin-readiness scan . \
  --owners owners.csv

Across many systems

Merge the CBOMs of every system, including ones made by other tools, into one ranked inventory.

acxelin-readiness merge out-a out-b \
  --name "Example Bank"

What it does not claim

  • A scan cannot prove cryptography is absent. Code that builds algorithm names at run time, or loads them from outside the scanned files, can be missed.
  • Static analysis shows what your files say, not what runs in production. Live endpoint scans close part of that gap.
  • It never changes your files and never sends them anywhere. It reports where key material sits and of what kind, never the key itself.

Start with one repository

Install it, scan a folder or a GitHub repository, and open the report. The console does the same without the command line, tracks an owner, service, status and due date for each finding, says how hard each change is, and shows every project, the services most at risk and the third-party libraries on one page.
