Set up Acxelin Readiness

It runs on Linux, Windows and macOS with Python 3.11 to 3.14. You do not need another Acxelin product, and nothing contacts Acxelin Quantum.

  1. Download

    From the release page, save two files in the same folder:

    • acxelin-readiness-{{VERSION}}-wheelhouse.tar.gz: the program
    • SHA256SUMS: a fingerprint of every file in the release

    Then open a terminal in that folder. On Windows, use PowerShell.

  2. Check the download

    This confirms the file is exactly the one we published, not damaged or changed on the way. It only reads the file.

    Linux

    sha256sum -c SHA256SUMS --ignore-missing

    You should see the file's name followed by OK.

    macOS

    shasum -a 256 acxelin-readiness-{{VERSION}}-wheelhouse.tar.gz

    Windows

    Get-FileHash .\acxelin-readiness-{{VERSION}}-wheelhouse.tar.gz

    On macOS and Windows this prints the file's fingerprint, a long string of letters and numbers. It should match the one next to the file's name in SHA256SUMS (capital or small letters do not matter).

    If the check fails, delete the file and download it again. Do not install it.

    Optional: confirm who built it

    If you use the GitHub command line, this shows that our release workflow built the file from this repository:

    gh attestation verify acxelin-readiness-{{VERSION}}-wheelhouse.tar.gz --owner AcxelinQuantum

    You should see Verification succeeded.

  3. Unpack it

    tar xzf acxelin-readiness-{{VERSION}}-wheelhouse.tar.gz
cd acxelin-readiness-{{VERSION}}-wheelhouse

    This creates the folder acxelin-readiness-{{VERSION}}-wheelhouse and moves into it. The same two lines work in PowerShell.

  4. Install

    Still in that folder:

    sh install.sh

    On Windows, the first line tells Windows you trust this downloaded script, and the second runs it:

    Unblock-File .\install.ps1
powershell -ExecutionPolicy RemoteSigned -File .\install.ps1

    It installs from the wheels in the folder, offline, then runs acxelin-readiness doctor. You should see each check and Start here with the next commands.

    What it changes
    A private Python environment in ~/.acxelin/readiness and the command ~/.local/bin/acxelin-readiness. On Windows, %LOCALAPPDATA%\Acxelin\readiness and %LOCALAPPDATA%\Acxelin\bin, which it adds to your user PATH. No administrator rights, nothing system-wide.
    OpenSSL 3.5
    Optional. Scans of code, configuration, keys and most endpoints need nothing extra. See reading certificates of post-quantum-only servers below.
    Remove it
    sh install.sh --uninstall, or install.ps1 -Uninstall. Your reports and settings stay where you put them.

  5. Scan a repository

    acxelin-readiness scan path/to/repository

    Open readiness-out/report.html in a browser. The CBOM and SARIF files are next to it. The folder holds short code snippets, so treat it as you treat the code.

  6. Open the console

    acxelin-readiness console

    Your browser opens already signed in. The first time, choose the folder that holds your repositories, add one, and scan it. The Endpoints tab grades live servers and shows what changed since the last check.

    On a remote server

    The console listens only on the machine it runs on. Forward a port, then ask the running console for a fresh link:

    ssh -L 8900:127.0.0.1:8900 server
acxelin-readiness console link --port 8900

    Run the second command in that SSH session and open the address it prints on your laptop.

    In Docker

    docker run --rm -v "$PWD:/scan" ghcr.io/acxelinquantum/acxelin-readiness:{{VERSION}}

    On Linux, add --user "$(id -u):$(id -g)" after --rm so the scan can write readiness-out into your folder; Docker Desktop on Windows and macOS needs nothing extra.

    For the console, start it with --container and publish its port to loopback only, then ask it for a link:

    docker run -v readiness:/data -p 127.0.0.1:8900:8900 ghcr.io/acxelinquantum/acxelin-readiness:{{VERSION}} console --container
docker exec -it NAME acxelin-readiness console link

  7. Gate pull requests

    Pin the action to the release you installed, so the check you trust is the check that runs:

    - uses: AcxelinQuantum/AQPQCSuite/products/readiness@readiness-v{{VERSION}}
  with:
    fail-on: high
    baseline: cbom.json

    The action uploads the SARIF file to code scanning and fails only on cryptography the pull request adds.

  8. Configure

    Put settings in .acxelin-readiness.toml at the root of the folder you scan. Every key is optional.

    exclude = ["generated", "*.min.js"]
tls = ["api.example.com:443"]
fail_on = "high"

[policy]
profiles = ["nist-ir-8547"]
forbid = ["MD5", "SHA-1"]

    Before you scan systems you do not own, read what Acxelin Readiness does with your code, and get written permission for every endpoint.

Reading certificates of post-quantum-only servers

Grades, accepted groups and SSH algorithms need nothing extra. To read the certificate of a server that offers only post-quantum key exchange, Acxelin Readiness completes a real TLS 1.3 handshake through OpenSSL 3.5 or newer. Point ACXELIN_OPENSSL at the folder that holds it, and run acxelin-readiness doctor to see whether it is found.

Without it, the report says those certificates were not observed. It never marks them as passing.
