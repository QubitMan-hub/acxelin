Set up Acxelin VPN

Gateways need Linux, and the gateway image has everything else. People's computers need the desktop app and WireGuard. The administrator's command line needs Python 3.11 to 3.14 and OpenSSL 3.5 or newer. Nothing contacts Acxelin Quantum.

  1. Download

    From the release page, save two files in the same folder:

    • acxelin-vpn-{{VERSION}}-wheelhouse.tar.gz: the program
    • SHA256SUMS: a fingerprint of every file in the release

    Then open a terminal in that folder. On Windows, use PowerShell. The desktop installers for people's computers are on the same page and are checked the same way.

  2. Check the download

    This confirms the file is exactly the one we published, not damaged or changed on the way. It only reads the file.

    Linux

    sha256sum -c SHA256SUMS --ignore-missing

    You should see the file's name followed by OK.

    macOS

    shasum -a 256 acxelin-vpn-{{VERSION}}-wheelhouse.tar.gz

    Windows

    Get-FileHash .\acxelin-vpn-{{VERSION}}-wheelhouse.tar.gz

    On macOS and Windows this prints the file's fingerprint, a long string of letters and numbers. It should match the one next to the file's name in SHA256SUMS (capital or small letters do not matter).

    If the check fails, delete the file and download it again. Do not install it.

    Optional: confirm who built it

    If you use the GitHub command line, this shows that our release workflow built the file from this repository:

    gh attestation verify acxelin-vpn-{{VERSION}}-wheelhouse.tar.gz --owner AcxelinQuantum

    You should see Verification succeeded.

  3. Unpack it

    tar xzf acxelin-vpn-{{VERSION}}-wheelhouse.tar.gz
cd acxelin-vpn-{{VERSION}}-wheelhouse

    This creates the folder acxelin-vpn-{{VERSION}}-wheelhouse and moves into it. The same two lines work in PowerShell.

  4. Install

    On the administrator's computer, still in that folder:

    sh install.sh

    On Windows, the first line tells Windows you trust this downloaded script, and the second runs it:

    Unblock-File .\install.ps1
powershell -ExecutionPolicy RemoteSigned -File .\install.ps1

    It installs from the wheels in the folder, offline, then runs acxelin-vpn doctor. You should see each check and Start here with the next commands.

    What it changes
    A private Python environment in ~/.acxelin/vpn and the command ~/.local/bin/acxelin-vpn. On Windows, %LOCALAPPDATA%\Acxelin\vpn and %LOCALAPPDATA%\Acxelin\bin, which it adds to your user PATH.
    Gateways
    Pull ghcr.io/acxelinquantum/acxelin-vpn:{{VERSION}}, or install on the host with the systemd units in deploy/systemd; the manual has both.
    Remove it
    sh install.sh --uninstall, or install.ps1 -Uninstall. Your authority, certificates and settings stay where you put them.

  5. Create your certificate authority

    The authority signs a certificate for every gateway and every person. Only certificates it signed can join your VPN.

    acxelin-vpn ca init --name "Acme VPN Root" --dir pki

    It asks you to choose a passphrase, which protects the authority's key. Keep it somewhere safe: you need it to issue or revoke certificates. The folder pki now holds the authority; only you should be able to read it.

  6. Issue a certificate for each gateway

    Give each site's gateway its name and its public address. These are the example sites; use your own:

    acxelin-vpn ca issue site hq.acme.example --san 203.0.113.10 --dir pki --out pki/issued/hq
    acxelin-vpn ca issue site branch1.acme.example --san 198.51.100.7 --dir pki --out pki/issued/branch1

    Each gateway gets its own folder under pki/issued. Copy that folder to the gateway, with pki/ca.crt and pki/crl.pem. The authority's key never leaves pki.

  7. Connect the two sites

    On each gateway, put its settings in /etc/acxelin-vpn/site.toml. Start from config/site-hq.toml or config/site-branch.toml in the release folder; every setting is explained there. Then start the VPN:

    docker run -d --name vpn --network host --cap-add NET_ADMIN -v /etc/acxelin-vpn:/etc/acxelin-vpn:ro ghcr.io/acxelinquantum/acxelin-vpn:{{VERSION}}

    It runs in the background. To see whether the tunnel is up:

    docker exec vpn acxelin-vpn status --config /etc/acxelin-vpn/site.toml

    It lists each tunnel: the other site, its state (ESTABLISHED when up), its key exchange, whether the post-quantum PPK is in use, and how long it has been up. Open UDP 500 and 4500 between the gateways, and TCP 7443 to headquarters. Then send real traffic between the two networks and check that the byte counters go up: a tunnel that is up but carries nothing is not yet proof.

  8. Let people connect

    People enroll once through the enrollment service, then connect to the WireGuard gateway. First, a certificate for the enrollment service, on the machine that holds the authority:

    acxelin-vpn ca issue server ca.acme.example --san ca.acme.example --dir pki --out pki/issued/enroll

    Then start the enrollment service there. It keeps running and listens on port 9443:

    acxelin-vpn ca serve --dir pki --cert pki/issued/enroll/chain.pem --key pki/issued/enroll/key.pem

    On the headquarters gateway, put the address pool, routes and DNS for people in /etc/acxelin-vpn/gateway.toml, starting from config/gateway.toml, and start the WireGuard gateway:

    docker run -d --name wg --network host --cap-add NET_ADMIN -v /etc/acxelin-vpn:/etc/acxelin-vpn ghcr.io/acxelinquantum/acxelin-vpn:{{VERSION}} gateway --config /etc/acxelin-vpn/gateway.toml

    Open UDP 51820 and TCP 7443 to the gateway, and TCP 9443 to the enrollment service.

  9. Invite a person

    This makes an invitation file for Alice. It tells her computer where to enroll and which gateway to use:

    acxelin-vpn invite alice --dir pki --enroll https://ca.acme.example:9443 --gateway vpn.acme.example:7443

    You get alice.acxinvite. It works once, within 24 hours, so send it through a channel you trust. Alice installs the desktop app and WireGuard, opens the file, chooses a passphrase and presses Connect. Her window then says Protected.

  10. Open the console

    The console shows your sites and people in the browser: each tunnel and who is connected, and the People tab to invite or revoke someone.

    acxelin-vpn console

    Your browser opens, already signed in. Add each gateway by its status address to see its tunnels.

    On a remote machine, forward port 8901 over SSH, then run this there and open the address it prints:

    acxelin-vpn console link --port 8901

  11. Keep it running

    Once a day, the authority must renew certificates that are close to expiring and publish a fresh revocation list. A gateway whose revocation list has expired refuses everyone.

    acxelin-vpn ca maintain --dir pki

    The release folder has a daily timer that runs it for you. Before a wide rollout, test sleep and wake, a Wi-Fi change, a gateway restart and a revocation on the computers you actually use, and read what Acxelin VPN defends against.
